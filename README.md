# Invectus Benchmark

Invectus explores how an existing AI model can inspect and edit 3D geometry. This repository specifies its first benchmark against Blender/MCP. The task is to reshape a character's hood toward a reference silhouette under the same edit budget and geometry checks.

[Постановка Invectus и структура первого PR](PROJECT_CHARTER.md)

## Задача первого PR

Devin Bots должен собрать воспроизводимый прогон на двух уже смоделированных капюшонах. В каждом случае модель меняет задний контур по референсу в профиль и сохраняет лицевой вырез и голову. Первый меш используется для разработки, второй — для проверки с зафиксированными правилами.

Invectus связывает цветной рендер и глубину с постоянными ID граней. Выбор пикселя возвращает ближайшую грань. При перекрытии прототип предлагает ракурс с большей видимостью выбранной области. Изнанку можно посмотреть в сечении рендера. Модель выбирает область и смещение, а оператор плавно уменьшает смещение вдоль рёбер к границе области.

## Условия сравнения

- В каждой ветке три прогона на каждом из двух мешей. Модель, настройки, входная сцена, референс, закреплённые вершины и бюджет совпадают.
- Blender/MCP использует свои инструменты просмотра и редактирования. Invectus использует ракурсы, связанные с ID граней, и локальную деформацию. Каждая ветка предлагает до трёх правок за прогон. Отклонённая правка расходует попытку.
- Обе ветки передают предложенное смещение вершин одному валидатору. Для одной правки он пробует коэффициенты `1`, `1/2`, `1/4` и `1/8` и применяет первый допустимый вариант. Если допустимого варианта нет, текущая форма сохраняется.

## Проверка меша

Связность проверяется на входе и сохраняется при деформации. У внутреннего ребра две грани, у граничного одна, а окрестность вершины образует один веер или кольцо. На каждом пробном шаге валидатор проверяет положения закреплённых вершин, самопересечения капюшона и пересечения с головой. Допустимый контакт между соседними треугольниками ограничен их общей вершиной или ребром.

У каждой затронутой грани площадь должна составлять хотя бы 20% площади той же грани во входной сцене, а минимальная высота — хотя бы 5% её длиннейшего ребра. Автотесты проверяют выбор ближайшей грани в месте перекрытия, сохранение лицевого выреза и отбраковку пробного шага, который пересекает голову.

## Как засчитывается выигрыш

Камера, разрешение и зона затылка фиксируются в настройках сцены. Ошибка `E` — среднее симметричное расстояние в пикселях между контуром капюшона и контуром референса в этой зоне. Пустой контур получает штраф в диагональ кадра. Для каждой сцены исходная ошибка `E_start` положительна.

```text
gain = (E_start - E_final) / E_start
```

Откат к исходной форме даёт `gain = 0`. В отчёт входят все прогоны. На каждом из двух мешей медианное улучшение Invectus должно быть не менее 20% и превышать медианное улучшение Blender/MCP минимум на 10 процентных пунктов. Выигрыш оценивается по итоговому контуру при общих правилах валидации.

Запланированная точка входа — `python -m bench.compare`. Она сохраняет рендеры до и после, наложение контуров, оценки каждого прогона и причины отклонения пробных шагов.
